# CRM заказов брелков — Mini App в Telegram

Дата: 2026-11-16. Статус: согласовано («делай, как знаешь» — решения исполнителя отмечены как *решение*).

## Зачем

Работа с заказами живёт в Telegram-чате: подписи сообщений — единственное хранилище, правка через бота неудобна
(шаблон текстом не прижился), стадии — это перенос сообщений между темами с удалением оригинала.
Нужна мини-CRM на двоих, открываемая прямо в Telegram:

- **Владелец** — маркетинг, приём и обработка новых заказов (согласует всё с клиентом в переписке).
- **Компаньон** — производство, выдача и отправка почтой.

Успех: оба открывают одно приложение, видят все заказы по стадиям, правят любое поле отдельно, двигают заказ дальше
одной кнопкой (или перетаскиванием на компьютере), оставляют комментарии.

## Цели

1. Все заказы с сайта сразу попадают в базу (Supabase) и в CRM.
2. Доска из 5 колонок: 🆕 Новые → 🛠 В производстве → 🏪 Готов к выдаче / 📦 Готов к отправке → ✅ Завершён.
   «Готов» разделён по способу доставки (решение владельца): самовывоз и такси → «к выдаче», Poșta Moldovei и
   Nova Poshta → «к отправке». В базе это одна стадия `ready`; колонка выбирается по `method`, поэтому смена доставки
   сама переносит заказ между колонками. «Уточнит позже» (`later`) — в «к выдаче» с пометкой «способ не выбран».
3. Карточка заказа: каждое поле правится отдельно; доставка — сначала способ кнопками, потом только нужные поля.
4. Комментарии к заказу и история изменений (кто, что, когда).
5. Открывается как Mini App внутри Telegram (телефон и Telegram Desktop), доступ только у двух человек.
6. Прошлые заказы (выгрузка чата за ноябрь, 25 шт.) перенесены в CRM.

## Не цели

- Колонки «Согласование» и «Отменён» (владелец так решил). Тест/спам/отказ → «Завершён» с комментарием.
- Оплаты, склад, аналитика, CRM на румынском (интерфейс только русский — *решение*).
- Отдельное приложение/репозиторий (выбран вариант «в составе сайта»).
- Supabase Realtime (обновление опросом — *решение*, см. ниже).

## Анти-цели (провал, даже если «работает»)

- **Удалён хотя бы один PDF или сообщение с заказом в чате.** Жёсткий запрет владельца. В коде CRM и бота нет
  ни одного удаления сообщения с заказом, ни одного удаления файла в хранилище, ни одного `DELETE` по заказам.
- Заказ с сайта потерян из-за сбоя базы (база недоступна → заказ всё равно уходит в Telegram).
- Посторонний открыл CRM по ссылке и увидел телефоны клиентов.
- Затронуты данные других проектов Supabase или старая таблица `public.orders`.

## Варианты (выбран A)

- **A. Раздел сайта `/crm`, открывается как Mini App (выбран).** Один проект Vercel и один деплой; переиспользуется
  код дат, телефона, доставки; заказ с сайта сразу пишется в базу. Минус: CRM и сайт выкатываются вместе.
- **B. Отдельное приложение.** Независимо, но две кодовые базы и дублирование логики — лишнее для двух пользователей.
- **C. Готовая CRM (Trello/Notion/amoCRM).** Не в Telegram, не знает доставку/даты/PDF, абонплата.

## Ограничения и среда

- Supabase: проект **Wasilevz's Project** (`uvuavmzrxtyvsytzjywk`, eu-west-1). В нём только пустая `public.orders`
  (не трогаем) и пустое хранилище. Новые таблицы — с префиксом `crm_`.
- Free-тариф Supabase: 2 активных проекта (сейчас активны этот и pastry-ai; Rabota на паузе).
- Vercel, Next.js 16 / React 19 / Tailwind 4, без лишних зависимостей. Новая зависимость — только `@supabase/supabase-js`
  (на сервере). Перетаскивание — нативный HTML5 drag&drop (на компьютере), на телефоне — кнопки.
- Telegram не разрешает кнопку `web_app` в группах → кнопка-ссылка на прямой адрес Mini App
  `https://t.me/<bot>/crm?startapp=<код заказа>` (приложение регистрируется в BotFather командой `/newapp`).

## Архитектура

```
Сайт (форма) ──POST /api/order──► Supabase crm_orders (+PDF в Storage) ──► Telegram: сообщение с PDF + кнопка «Открыть в CRM»
                                         ▲
Telegram Mini App (/crm) ──fetch /api/crm/* (initData)──┘──► правка подписи сообщения в чате (стадия, поля) — без удалений
```

- Клиент CRM не ходит в Supabase напрямую. Все запросы — к API-маршрутам сайта `/api/crm/*`, которые работают
  с базой сервисным ключом (`SUPABASE_SERVICE_ROLE_KEY`, только на сервере). RLS на таблицах `crm_*` включён без
  политик — анонимный ключ ничего не видит (*решение*).
- **Вход:** каждый запрос несёт заголовок `X-Telegram-Init-Data` (строка `Telegram.WebApp.initData`). Сервер проверяет
  подпись HMAC-SHA256 по токену бота (алгоритм Telegram для Mini Apps), свежесть `auth_date` ≤ 24 ч и что `user.id`
  есть в `CRM_ALLOWED_USER_IDS` (обязательная переменная; пустая → доступ закрыт всем). Вне Telegram — экран
  «Откройте через Telegram». Для локальной разработки: `CRM_DEV_USER_ID` работает только при `NODE_ENV !== "production"`.
- **Обновление:** доска перезапрашивает данные каждые 20 с, пока вкладка видима, и сразу после любого действия.

Комментарии только добавляются (без правки и удаления — *решение*, проще и соответствует запрету на удаления).

`<code>-2.pdf`). Открытие — через подписанную ссылку на 10 минут, выдаёт `/api/crm/orders/<code>/pdf` (*решение*).

## Поведение

**Новый заказ с сайта** (`/api/order`): как сейчас собирает PDF и отправляет в Telegram, плюс:
1. Пишет строку в `crm_orders` (stage `new`) и загружает PDF в Storage. Сбой базы/хранилища **не** ломает заказ:
   заказ всё равно уходит в Telegram, в подпись добавляется строка `⚠️ Не записан в CRM`, ошибка в лог.
2. Сообщение в Telegram — с одной кнопкой-ссылкой «📋 Открыть в CRM» (`https://t.me/<bot>/crm?startapp=<code>`).
   `message_id` сохраняется в заказ.
3. Апселл со страницы «Спасибо» (`/api/telegram`) ставит `qty = 2` в базе и, как сейчас, правит подпись.
   Отложенное удаление служебного уведомления об апселле остаётся (это не сообщение заказа) — *решение*.

**Бот в чате** — без удалений сообщений с заказами:
- `moveOrder` и любые `deleteMessage` по сообщениям заказов удаляются из кода. Старые кнопки под прошлыми заказами
  (Готов/Выдан/Назад/Изменить/Заметка/Убрать 2-й) при нажатии отвечают «Заказы теперь ведутся в CRM» и меняют
  клавиатуру сообщения на кнопку «📋 Открыть в CRM» (если заказ есть в базе).
- Подпись сообщения заказа обновляется при каждом изменении в CRM: поля (через `setFieldLines`), строка
  `📌 Стадия: 🛠 В производстве`, количество брелков. Ошибка правки подписи (например, сообщение слишком старое)
  не мешает сохранению в CRM.

**Доска** (`/crm`):
- Телефон: вкладки колонок со счётчиками, одна колонка; компьютер (≥ 1024 px): 5 колонок рядом, перетаскивание.
  Перетаскивание в «к выдаче» заказа с почтой (и наоборот) ставит стадию `ready`, а карточка встаёт в свою колонку
  по способу доставки, с подсказкой «Способ доставки — почта, заказ в «Готов к отправке»».
- Карточка в списке: код, имя, срочность и дата, способ получения, количество брелков (если > 1), число комментариев.
- Порядок: срочные → по дате получения (ближе — выше, без даты — ниже) → по времени создания.
- «Завершён» показывает последние 30 дней, кнопка «Показать ещё».
- Поиск сверху: по имени, телефону, коду.
- `startapp=<код>` сразу открывает карточку этого заказа.

**Карточка заказа**:
- Поля: имя, телефон (кнопка «позвонить» `tel:`), нужен к + срочно, доставка (способ кнопками → поля способа:
  почта — индекс/город/район из списка/улица; Nova Poshta — отделение; такси — адрес), количество брелков, цена,
  источник (только чтение), язык клиента, PDF-макет (открыть), ссылка на сообщение в чате.
- Каждое поле редактируется отдельно (нажать → поле ввода → «Сохранить»/«Отмена»). Проверки — те же правила,
  что на сайте (`lib/phone.ts`, `lib/delivery-dates.ts`), но для менеджера дата может быть любой будущей и прошлой
  (*решение*: менеджер знает лучше; предупреждение, если дата раньше ближайшей для способа).
- Кнопки стадий: крупная «→ <следующая стадия>» и «← назад».
  Кнопка из «В производстве» называется по способу: «→ Готов к выдаче» или «→ Готов к отправке».
- Комментарии: список и поле «Добавить комментарий». История: свёрнутый список изменений.
- Все изменения пишутся в `crm_history` с именем пользователя Telegram.

**PDF — максимально быстро (главное требование владельца)**: «нажал, открыл, сохранил, готово».
- Кнопка **«⬇️ Скачать PDF»** — первая и самая крупная в карточке, и маленькая иконка ⬇️ прямо на карточке в списке
  (скачать, не открывая заказ). Вызывает `Telegram.WebApp.downloadFile({ url, file_name: "Brelok_<code>.pdf" })` —
  родной диалог сохранения Telegram (Bot API 8.0+). На старых клиентах — `Telegram.WebApp.openLink(url)`.
  `url` — подписанная ссылка Storage на 10 минут с `download=Brelok_<code>.pdf` (заголовок «скачать как файл»).
- Кнопка **«📩 Прислать в Telegram»** — бот присылает этот PDF нажавшему в личный чат с ботом, как документ
  (ровно тот опыт, что сейчас в чате). Для заказов с сообщением в группе — `copyMessage` из группы в личку
  (работает и для старых заказов, у которых PDF нет в Storage; оригинал не трогается). Если человек ни разу не писал
  боту, подсказка «Откройте бота и нажмите Start».
- Для импортированных заказов без PDF в Storage «Скачать» скрыта, остаётся «Прислать в Telegram» и ссылка на сообщение.
- Позже (не в этой версии): автоматически присылать PDF компаньону в личку, когда заказ уходит «В производство».

**Импорт прошлых заказов**: скрипт `scripts/import-telegram-export.mjs <result.json>` (запускается владельцем один раз
или исполнителем через Supabase MCP): разбирает выгрузку функцией `fieldsFromCaption`, пишет заказы с флагом
`imported`, датой сообщения и стадией: тема «Завершены» → `done`, «В работе» → `production`, сообщения до
появления тем (старая группа) → `done`. Повторный запуск не создаёт дублей (`code` уникален → пропуск). Файл выгрузки содержит телефоны клиентов —
в репозиторий не коммитится; владелец заново прикладывает `result.json` в сессию разработки.
PDF прошлых заказов остаются только в Telegram (в выгрузке их нет); в карточке — ссылка на сообщение в чате
(`https://t.me/c/<id группы без -100>/<message_id>`), если сообщение из текущей супергруппы.

## Настройка (делает владелец, шаги в README)

1. Vercel → Environment Variables: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (Supabase → Project Settings → API),
   `CRM_ALLOWED_USER_IDS` (id владельца и компаньона — бот покажет их по команде `/id` в личке), `TELEGRAM_BOT_USERNAME`.
2. BotFather → `/newapp` → бот → short name `crm`, URL `https://photobrelok.com/crm`.
3. (Один раз) импорт ноябрьской выгрузки.
