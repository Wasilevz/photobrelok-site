# Анимации PHOTOBRELOK

Цель анимаций — ответить клиенту на вопрос: «моё действие сработало?», «что изменилось?», «что делать дальше?». Если анимация ни на что не отвечает — не добавляй её.

## Где что лежит

- `public/landing.css`, в конце блок **Motion layer** — анимации лендинга (`components/Landing.tsx`), всё под `.pb`.
- `app/globals.css` — анимации вне `.pb`: форма заказа (`dialog.order-dialog`), конструктор (`components/PhotoConstructor.tsx`), плашка cookie, страница `/thanks`.
- Появление блоков при прокрутке: атрибут `data-stagger` на контейнере → его прямые дети выезжают по очереди. JS в `Landing.tsx` ставит `.motion-ready` на `.pb` и `.is-in` на контейнер через IntersectionObserver.
- Плагина `tailwindcss-animate` в проекте **нет**: классы `animate-in`, `fade-in`, `zoom-in`, `slide-in-from-*` ничего не делают. Используй свои классы.

## Готовые классы (переиспользуй, не плоди новые)

| Класс | Где | Что делает |
|---|---|---|
| `data-stagger` | лендинг | очередь появления детей при прокрутке |
| `.pb-panel-in` | везде | раскрывающаяся панель: fade + 6px сверху, 200 мс |
| `.pb-toast-in` | везде | сообщение/тост: fade + 16px снизу, 280 мс |
| `.pb-sheet-in` | везде | лист снизу экрана (cookie) |
| `.pb-card-in` | везде | крупная карточка: fade + подъём + scale 0.97 |
| `.pb-develop-in` | конструктор | фото «проявляется» в кадре плёнки |
| `.pb-main-cta`, `.cta-swap` | кнопки | мягкая смена текста кнопки (перемонтируй через `key`) |
| `.pb-check-pop`, `.pb-sparkle` | `/thanks` | момент успеха |

## Тайминги и кривые (единый язык движения)

- Кривая по умолчанию: `cubic-bezier(0.22, 1, 0.36, 1)` (`--ease-out-soft` в `.pb`). Пружина для редких «радостных» моментов: `cubic-bezier(0.34, 1.25, 0.64, 1)` — не сильнее.
- Наведение, нажатие, переключатели: 100–200 мс. Панели и меню: 150–250 мс. Диалоги и тосты: 200–350 мс. Появление блоков: 300–500 мс.
- Уход быстрее появления примерно на треть.
- Очередь: 20–60 мс на элемент (сейчас 45 мс), вся цепочка ≤ ~0.5 с.
- Нажатие: `scale(0.97)` с `transition-duration: 0.06s`.
- Сдвиг при появлении 6–24 px, масштаб от 0.95–0.98, никогда от 0.

## Правила

1. Анимируй только `transform` и `opacity`. Не `width/height/top/left/margin`. Прогресс — через `scaleX` + `transform-origin: left`.
2. Ховер-эффекты — только внутри `@media (hover: hover)`, чтобы на телефоне ничего не «залипало».
3. Всё новое — внутри `@media (prefers-reduced-motion: no-preference)` или с учётом глобального правила в начале `landing.css`, которое обнуляет длительности.
4. Контент не прячется навсегда: скрытие до появления ставится только из JS (класс `.motion-ready`). Без JS и при «уменьшить движение» всё видно сразу.
5. Не вешай `data-stagger` на элементы, которые перемонтируются при смене языка (ключи из переведённого текста) — вешай на стабильного родителя.
6. Не ставь `transform` на предков `position: fixed` элементов (конструктор, панели) — это ломает фиксацию. Секцию `#builder` не анимировать целиком.
7. Анимации с `animation-fill-mode` — `backwards`, а не `both`: иначе финальный `transform: none` перебивает ховеры.
8. Бесконечные циклы рядом с текстом запрещены (максимум 2–3 повтора). Ничего не мигает чаще 3 раз в секунду.
9. Первый экран (hero): только короткое появление, видео и `h1` не прятать надолго — это LCP.

## Проверка (обязательно перед коммитом)

1. `npx tsc --noEmit -p . && npx eslint <изменённые файлы>`
2. `npx next dev --webpack -p 3123`, затем Playwright (`require('playwright')`, `devices['iPhone 13']`):
   - прокрутить страницу целиком → все `[data-stagger]` получили `.is-in`, ни один ребёнок не остался с `opacity: 0`;
   - переключить язык (`[data-testid=lang-switch]`) → ничего не пропало;
   - `reducedMotion: 'reduce'` → `.pb` без `.motion-ready`;
   - для конструктора: загрузить 6 фото через `#constructor input[type=file]`, подтверждая каждое окно кадрирования (последняя кнопка в `div.fixed.inset-0.z-[10000]`).
3. Посмотреть скриншот в середине анимации и после неё.
